# MindSpeed MM FAQ

| No. | Issue Summary | Impact | Current Solution | Future Plan | Reference |
|:------:|:------:|:------:|:------:|:------:|:------:|
| 1 | Training errors caused by CANN version mismatch | Training cannot start or operator errors occur | Ensure that the driver and firmware, CANN Toolkit/Kernels/NNAL, PyTorch, and TorchNPU versions match strictly. For details, see [Version Compatibility Description](../../release_notes_mm.md#related-product-version-compatibility) | Continuously update the version compatibility table | [Installation Guide](../installation/install_guide.md) |
| 2 | `ModuleNotFoundError: No module named 'acl'` | Ascend-related modules cannot be imported | Check whether `source /usr/local/Ascend/ascend-toolkit/set_env.sh` has been executed. It is recommended to add the command to `~/.bashrc` | - | [Installation Guide](../installation/install_guide.md) |
| 3 | `libatb.so` cannot be found due to an incorrect installation order of the CANN nnal package | Dynamic library missing errors occur during inference or training | The nnal package must be installed after `source /usr/local/Ascend/ascend-toolkit/set_env.sh`; otherwise, the dependency path cannot be found | - | [Installation Guide](../installation/install_guide.md) |
| 4 | Script hangs without error when launching multi-node multi-device training | Unable to start distributed training | Ensure `pdsh` is installed; otherwise, the multi-node multi-device launch script will hang. Install via `apt install pdsh` or `yum install pdsh`. | - | - |
| 5 | HuggingFace weights cannot be used directly for training | Training fails to start | The HuggingFace weight format (safetensors/bin) cannot be used directly for Megatron architecture training. Use the `mm-convert` tool to convert the weights to the MindSpeed MM format | - | [Weight Conversion](../../tools/mm_convert.md) |
| 6 | TP/PP parameters used for weight conversion are inconsistent with those used for training | Loading weights for training fails | The `tp_size`, `pp_size`, and `llm_pp_layers`/`vit_pp_layers` used for weight conversion must be consistent with the parallel configuration in the training script | - | [Weight Conversion](../../tools/mm_convert.md) |
| 7 | `tp_size` exceeding `num_key_value_heads` | Tensor parallel sharding fails. |  `tp_size` cannot exceed `num_key_value_heads` in the model configuration; otherwise, KV heads cannot be evenly distributed across cards. | - | - |
| 8 | The number of weight files after training is inconsistent with that of the original HF model | Users wonder whether the weights are complete | Training produces Megatron-Core (Mcore) format weights, which are converted to the standard HF format by mg2hf. The number of files varies with the sharding strategy, but the parameters are complete. You need to regenerate `model.safetensors.index.json` | - | [Weight Conversion](../../tools/mm_convert.md) |
| 9 | Insufficient NPU memory (OOM) | Training interrupted | Take the following measures: 1. Reduce `micro-batch-size` (to a minimum of 1); 2. Increase the TP/PP parallelism (TP×PP≤number of NPUs); 3. Reduce `seq-length`; 4. Enable recomputation (`--recompute-granularity full --recompute-method block --recompute-num-layers`); 5. Use ChunkLoss to reduce the peak memory usage | - | [ChunkLoss](../../features/optimization/chunkloss.md) |
| 10 | `learning_rate=None` assertion error when LLM PP is sharded to 0 layers | Training crashes immediately after startup. | The LLM part in the PP sharding configuration cannot have a stage with 0 layers. For example, `llm=[0,8,10,10]` causes this issue. Adjust to `llm=[1,7,10,10]` to ensure each stage has LLM layers. | Optimize the learning rate loading logic to support 0-layer stages. | - |
| 11 | Data preprocessing timeout or synchronization error | Training cannot start with large datasets | Increase `--distributed-timeout-minutes`. For very large datasets (millions of samples or more), preprocess in batches or use higher-performance storage. | Optimize data preprocessing parallel efficiency. | - |
| 12 | Incorrect NIC name causing communication timeout | Multi-node training cannot start. | Use `ifconfig` to check the NIC name and set the corresponding environment variables: `export HCCL_SOCKET_IFNAME=<NIC name>`, `export TP_SOCKET_IFNAME=<NIC name>`, `export GLOO_SOCKET_IFNAME=<NIC name>`. | - | - |
| 13 | Timeout error when saving checkpoints | Weight saving fails after training. | Ensure normal disk I/O bandwidth. A single node's maximum file size of approximately 60GB must be saved within 36 minutes. This error can also be ignored as it does not affect the saved weights. | - | - |
| 14 | `syntax error near unexpected token` after a script copy | Script cannot be executed. | Line endings mismatch when a script is copied from Windows to Linux. Execute `dos2unix xxx.sh` or set `:set ff=unix` in vim | - | - |
| 15 | Environment variable conflicts between different CANN versions | Training anomalies in a multi-version environment | It is recommended to use Docker to isolate different versions of CANN packages to prevent environment variable interference. | - | - |
| 16 | Unbalanced load between fast and slow devices during multimodal model training | Low training efficiency | Use heterogeneous PP sharding for multimodal models, configuring different PP layer distributions for the vision encoder, audio encoder, and LLM respectively, to avoid overloading some devices | - | [Heterogeneous Parallelism](../../features/parallel/hetero_parallel.md) |
| 17 | Training loss not converged | Poor model performance | Check: 1. Data quality and cleaning logic; 2. Learning rate and warmup strategy; 3. Whether pretrained weights are used for initialization; 4. Whether data paths and image paths are correct. | - | - |
| 18 | Recommended key environment variable configurations | Impact on training performance and stability. | Recommended configurations: `export ASCEND_GLOBAL_LOG_LEVEL=1`, `export TASK_QUEUE_ENABLE=2`, `export CPU_AFFINITY_CONF=2`, `export HCCL_CONNECT_TIMEOUT=600`, and `export PYTORCH_NPU_ALLOC_CONF=expandable_segments:True`. | - | - |
| 19 | Megatron-LM version does not match MindSpeed MM | Errors during installation or running | MindSpeed MM requires a matching version of Megatron-LM. Check out the commit or tag specified in the [Installation Guide](../installation/install_guide.md) | - | [Installation Guide](../installation/install_guide.md) |
| 20 | Missing model-specific dependencies in the Docker image | Model training errors | The Docker image only contains pre-installed basic dependencies like torch, torch_npu, and decord. Additional dependencies must be manually installed in the base environment according to the target model's README. | - | - |
